# ميزان الأعمال — نظام الفواتير والمبيعات

تطبيق Android عربي باستخدام Kotlin وJetpack Compose، لإدارة المنتجات والعملاء والفواتير والذمم والمقبوضات. الإصدار الحالي 1.5.1 يدعم Android 8.0 وما بعده، ويعمل محليًا دون إنترنت.

- صنفا «رمل 1» و«رمل 2» مبدئيًا، دون أسعار أو معاملات تجريبية.
- فواتير متعددة البنود وكميات عشرية وخصومات وضريبة اختيارية.
- دفعات نقدية وجزئية وآجلة، وتحصيل مرتبط بالفواتير دون تكرار المبيعات.
- مخزون اختياري، ومرتجعات وإلغاء وتصحيح الفواتير مع حفظ الأصل وسجل التدقيق.
- باركود بالكاميرا أو قارئ يعمل كلوحة مفاتيح، وطباعة ملصقات Code 128 وQR.
- فواتير وكشوف حساب وسندات قبض PDF عربي، مع تنزيل ومشاركة وطباعة A4 و58mm و80mm.
- تقارير Excel بصيغة XLS وCSV وPDF، وواجهة RTL فاتحة وداكنة.
- نسخ احتياطي واستعادة ونقل البيانات، وترحيل اختياري من قاعدة النظام القديم مع حفظها وأرشفتها.

## التشغيل

افتح المشروع في Android Studio مع JDK 21 وAndroid SDK 36، أو استخدم:

```sh
./gradlew :app:assembleDebug
```

ملف الاختبار: `app/build/outputs/apk/debug/app-debug.apk`.

تجهيز Release يتطلب مفتاح النشر الأصلي عبر إعدادات آمنة. عند غيابه يفشل حاجز التوقيع؛ لا يوجد fallback إلى مفتاح Debug. لا تستخدم APK Release قديمًا في مجلد البناء كتسليم جديد. مفتاح آخر لا يصلح لتحديث التطبيق المنشور. نسخة Debug بمعرّف مستقل ولا تصل إلى بيانات نسخة Release.

النسخة اليدوية version=2 تشمل الدفتر الجديد وRoom القديم والإعدادات والشعار والصور والمرفقات؛ تُرفض الملفات التالفة أو المرتبطة المفقودة. حد الحزمة 50MB، ونسخ الأمان المحلية تُنزّل منفصلة. version=1 مدعوم مع تحذير أنه لا يتضمن ملفات القديم. الاستعادة الكاملة قد تتطلب إغلاق التطبيق وإعادة فتحه لتحديث Room وDataStore.

ديون الموردين القديمة لا تُدخل في المبيعات أو ذمم العملاء؛ تُحفظ في مسار مراجعة مع الأصل ودفعات المورد. تصحيح الترحيل الخاطئ السابق متاح من الإعدادات مع نسخة أمان وأثر تدقيق، ويرفض المعالجة الآلية إذا تعدلت الفواتير لاحقًا.

ابدأ بضبط سعر «رمل 1» ووحدته من المنتجات، ثم سجل أحمد وأصدر فاتورة 5 طن × 12 JOD مع دفع 25 JOD: المبيعات 60، المقبوضات 25، والذمة 35. تحصيل 35 لاحقًا يجعل المقبوضات 60 والذمة صفرًا وتبقى المبيعات 60.

## الاختبارات والحدود

```sh
./gradlew testDebugUnitTest :app:assembleDebug :app:lintDebug
```

النتيجة الحالية: 273 اختبارًا ناجحًا، وبناء Debug ناجح، وLint بلا أخطاء و112 تحذيرًا. التفاصيل وحدود الاختبار ومتطلبات التوقيع والأجهزة في [التدقيق بعد الإصلاح](docs/COMMERCE_AUDIT_AR.md). النسخة الحالية دفتر لمستخدم واحد وعملة واحدة، ونقل البيانات بين الأجهزة عبر النسخ الاحتياطي. ملفات PDF تحتوي صفحات مرسومة بالعربية المضمنة؛ النص فيها غير قابل للتحديد.
